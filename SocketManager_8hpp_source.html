13/**
14 * @file SocketManager.hpp
15 * @brief Declares the SocketManager and per-client state for non-blocking I/O.
16 *
17 * @details The SocketManager owns the event loop (based on `poll(2)`) and
18 * multiplexes:
19 * - listening sockets (bind/listen for each configured host:port),
20 * - accepted client sockets (read → parse → route → respond),
21 * - CGI subprocess pipes (lifecycle, timeouts, finalization),
22 * - write-side backpressure and keep-alive.
23 *
24 * Each connected client is tracked with a @ref ClientInfo structure
25 * that aggregates request/response buffers, timers, CGI state, and
26 * file-stream handles for zero-copy file responses.
27 *
28 * The implementation guarantees:
29 * - single `poll()` over all FDs, read & write monitored together,
30 * - non-blocking I/O for sockets and CGI pipes,
31 * - accurate HTTP status codes and default error pages,
32 * - resilient behavior under stress and strict timeouts.
33 *
34 * @ingroup socket_manager
35 */
36

129/**
130 * @brief Poll-driven socket and CGI orchestrator.
131 *
132 * @details
133 * Responsibilities:
134 * - Create and bind all listening sockets for configured servers.
135 * - Accept clients and maintain a single `poll()` set for all descriptors.
136 * - Receive, enforce limits, parse (supports pipelining), and route requests.
137 * - Spawn/manage CGI, enforce CGI timeout, collect output, finalize response.
138 * - Stream responses (raw / file) with keep-alive and backpressure handling.
139 * - Apply precise timeout policy (idle/header/body/send).
140 *
141 * Error handling strategy:
142 * - Never block; on I/O errors or protocol violations, push an error response
143 * and cleanly close when required.
144 * - Protect the loop with wide catch blocks—FDs are closed on failure paths.
145 *
146 * @ingroup socket_manager
147 */
