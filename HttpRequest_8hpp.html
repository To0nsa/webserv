Detailed Description

Immutable-ish HTTP/1.x request model with header map and parsed URL.

Represents a single HTTP/1.x request after (or while) being parsed by HttpRequestParser. The object stores:

  • Request line fields: method, path (raw target), and HTTP version.
  • Header fields in a case-preserving map (lookups are done via hasHeader and getHeader).
  • Optional message body and the tracked _contentLength.
  • A parsed Url object and extracted query string (text after ?).
  • A parser status code (_parseError) and the selected virtual server index (_matchedServerIndex) for routing (see requestRouter.*).
  • The resolved Host header value for vhost matching.

Typical lifecycle in this codebase:

  1. Bytes arrive on a socket and are parsed into HttpRequest by HttpRequestParser.*.
  2. requestRouter.* sets setMatchedServerIndex and may refine path/URL.
  3. Method handlers (handleGet.cpp, handlePost.cpp, handleDelete.cpp, plus handleMultipartForm.cpp / handleCgi.*) consume this object.
  4. responseBuilder.* uses fields (method, headers, body, URL) to craft an HttpResponse.
Invariants
  • If getParseErrorCode returns non‑zero, the request is considered malformed and the server should generate an appropriate error response.
  • getContentLength equals the numeric value derived from the Content-Length header if present; handlers must validate coherence with getBody.
  • getQuery is the substring of the request-target after ? (empty if absent). The raw getPath is not percent-decoded.
Note
This type is not thread-safe; owning code must synchronize externally.
