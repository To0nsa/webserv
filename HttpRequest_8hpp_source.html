13/**
14 * @file HttpRequest.hpp
15 * @brief Immutable-ish HTTP/1.x request model with header map and parsed URL.
16 *
17 * @ingroup http
18 *
19 * @details
20 * Represents a single HTTP/1.x request after (or while) being parsed by
21 * @ref HttpRequestParser. The object stores:
22 * - Request line fields: method, path (raw target), and HTTP version.
23 * - Header fields in a case-preserving map (lookups are done via @ref hasHeader
24 * and @ref getHeader).
25 * - Optional message body and the tracked @ref _contentLength.
26 * - A parsed @ref Url object and extracted query string (text after `?`).
27 * - A parser status code (@ref _parseError) and the selected virtual server
28 * index (@ref _matchedServerIndex) for routing (see `requestRouter.*`).
29 * - The resolved `Host` header value for vhost matching.
30 *
31 * Typical lifecycle in this codebase:
32 * 1. Bytes arrive on a socket and are parsed into @ref HttpRequest
33 * by `HttpRequestParser.*`.
34 * 2. `requestRouter.*` sets @ref setMatchedServerIndex and may refine path/URL.
35 * 3. Method handlers (`handleGet.cpp`, `handlePost.cpp`, `handleDelete.cpp`,
36 * plus `handleMultipartForm.cpp` / `handleCgi.*`) consume this object.
37 * 4. `responseBuilder.*` uses fields (method, headers, body, URL) to craft an
38 * @ref HttpResponse.
39 *
40 * @par Invariants
41 * - If @ref getParseErrorCode returns non‑zero, the request is considered
42 * malformed and the server should generate an appropriate error response.
43 * - @ref getContentLength equals the numeric value derived from the
44 * `Content-Length` header if present; handlers must validate coherence
45 * with @ref getBody.
46 * - @ref getQuery is the substring of the request-target after `?`
47 * (empty if absent). The raw @ref getPath is not percent-decoded.
48 *
49 * @note This type is not thread-safe; owning code must synchronize externally.
50 * @see HttpRequestParser, Url, HttpResponse, responseBuilder, requestRouter,
51 * handleGet, handlePost, handleDelete, handleCgi
52 */
