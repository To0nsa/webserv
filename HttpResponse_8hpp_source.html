35/**
36 * @brief Represents an HTTP response to be sent back to the client.
37 *
38 * @details Encapsulates all elements of an HTTP response:
39 * - **Status line**: numeric status code and reason phrase.
40 * - **Headers**: arbitrary key–value pairs such as `Content-Type` or `Content-Length`.
41 * - **Body**: inline string payload, file-backed content, or CGI-generated output.
42 * - **Metadata**: HTTP version, connection management, and offsets for CGI output.
43 *
44 * Provides a clear API for constructing responses via setters, and utilities
45 * for serializing them (`toHttpString`) or checking response type (file-backed
46 * vs. CGI temporary file).
47 *
48 * Typical workflow:
49 * - Built by method handlers (GET/POST/DELETE, CGI) or the @ref ResponseBuilder.
50 * - Sent by the networking layer after request handling.
51 *
52 * @ingroup http
53 */
